## 四、问题清单

### 🔴 阻断级

#### 1. WebDAV 明文 HTTP 会被平台层直接拦截（影响 F13 真实可用性）

- **现象**：`app/build.gradle.kts` 为 `targetSdk = 34`；`AndroidManifest.xml` 既无 `android:usesCleartextTraffic`，也无 `android:networkSecurityConfig`。Android 9（API 28）起默认 `cleartextTrafficPermitted = false`。
- **关键点**：`WebDavClient.buildClient()` 虽然加了 `ConnectionSpec.CLEARTEXT`，但 `ConnectionSpec` 只声明"协议允许"，**平台网络策略才是闸门**——`http://` 请求会抛 `Cleartext HTTP traffic to <host> not permitted`。
- **影响面**：E-Ink 阅读器 + 家用 NAS 这一主力场景，绝大多数是 `http://192.168.x.x:5005/webdav`。当前配置下用户填完地址点"立即同步"必然失败，且错误只体现在 summary 文案里，排查成本高。
- **建议修复**（二选一）：
  1. 新增 `res/xml/network_security_config.xml`，仅对 `https` 全局放行 + 允许用户配置的局域网域明文（更符合 F13 的实际使用）；
  2. 若坚持只支持 TLS，则在 `SettingsActivity.bindSync()` 对 URL 做 `https://` 前缀校验并给出明确提示，同步文档里写清"仅支持 HTTPS"。

### 🟠 重要级

#### 2. TalkBack / 无障碍未达标（Phase 1 明确项 + §9.2 验收第 8 条）

> **更正（2026-09-14）**：本条原表述「阅读页工具栏按钮、排版面板滑块均无 contentDescription」有误 —— 工具栏按钮与设置项带 `android:text`，**本身已可朗读**，不加 `contentDescription` 才是对的（加了反而覆盖原文案）。真正的缺口是 **SeekBar（只会读「seek bar, 40 percent」）、动态数值标签、列表项动作语义**。已按更正后的判断修正。

- 全工程 `app/src/main` 递归检索，`contentDescription` 命中 **1 处**（`ReaderActivity.kt:845` 目录项），`importantForAccessibility` / `AccessibilityNodeProvider` / `announceForAccessibility` **零命中**。
- 缺失点：`ShelfActivity.BookAdapter.Holder`（书架列表项）、`activity_shelf.xml` / `activity_reader.xml` 全部 Button、排版面板三个 SeekBar、`item_book` / `item_chapter`。
- §9.2 验收清单第 8 条要求"TalkBack 焦点顺序合理，控件**可读**"；Phase 1 路线图要求"TalkBack 控件可读基础支持"。当前**不满足**，且 §8 Phase 0 的"TalkBack 正文可读可行性评估"也未产出结论（R18 未闭环）。
- **建议**：Phase 4 前先补控件级 `contentDescription`（成本极低），正文可读按 R18 结论明确"仅控件可读"并写入文档。

#### 3. F18 的"手动导入设备配置"未接线

- `DeviceRepository.importProfiles(context, source)` 已实现（含 `readit_device_profiles_imported.json` 覆盖层），但 `SettingsActivity` 的 `bindReading` / `bindSync` / `bindInput` 三组里**没有任何入口**调用它。
- F18 验收标准为"内置 + 手动导入"，只完成了一半 → 该条不满足。

#### 4. PDF 渲染档真机性能基准缺失（R11 未闭环）

- 已完成的 `docs/P0-C 技术门禁报告.md` 只覆盖 **PdfBox 文本能力**（C1）。路线图 Phase 0 要求的是"PDF **文本**能力基准"，这条本身达标。
- 但 **F05 的验收标准（标准档渲染 + 裁边）在 A33 级 + 1GB 设备上从未实测**；R11"Pdfium A33 级渲染超时"（概率高 / 影响中）的缓解措施"文本/缩略图兜底 + 超时降级"只有兜底、**没有超时检测**——`PdfRenderView` 目前没有渲染超时看门狗，单页卡死会一直白屏。
- **建议**：为 `requestRender` 加超时（如 10s 无回调 → 提示并可退文本档），并在 Phase 4 真机矩阵里补 Pdfium 首屏/翻页耗时。

### 🟡 建议级

#### 5. F21 / §9.2 极限分辨率缺验证证据

`values-sw600dp` 已就位，但无 540×960 / 600×480 模拟器截图回归记录。属 Phase 4 范围，**当前不算欠账**，建议提前跑一遍（§9.2 第 5 条要求极限分辨率下"无溢出"）。

#### 6. APK 余量仅约 1.3 MB，Phase 4 极易破线

| APK | 体积 | 红线 | 余量 |
|---|---|---|---|
| `app-arm64-v8a-debug.apk` | 18.72 MB | 20 MB | 1.28 MB |
| `app-armeabi-v7a-debug.apk` | 18.56 MB | 20 MB | 1.44 MB |

构成分析（arm64 / 压缩后）：dex 7.09MB（37.9%）、**BouncyCastle 3.96MB（21.2%）**、native 3.14MB（16.8%）、pdfbox/fontbox 资源 1.74MB（9.3%）。BouncyCastle 经 `dependencyInsight` 确认是 `com.tom-roush:pdfbox-android:2.0.27.0` 的传递依赖。
Phase 4 还要加"引导 + 备份 + 设备收集工具"，破线风险实在。**不建议直接排除 BouncyCastle**（会导致加密 PDF `NoClassDefFoundError`，违反 F08 的"0 崩溃"）。可选：启用 R8/ProGuard 瘦身、裁剪 fontbox 未用的 cmap 资源。

#### 7. `MainActivity` 注释与实际用途已脱节

`eink/ui/MainActivity.kt` 内注释写"Phase 1 起将替换为书架 + 阅读器"，但实际它已作为**"设备信息"页**保留（Manifest 中 `android:label="@string/pref_device_info"`，由设置页 `device_info` 项进入），启动器早已是 `ShelfActivity`。建议更新注释避免后续误判。

#### 8. F13 的凭据明文存储 + 目录跳转无量化验证

- `ReadItPrefs.webDavPassword` 以明文写入 SharedPreferences（与 Book Keeper 同一取舍）。F13 未强制要求加密，但建议显式在文档标注风险，或改用 `EncryptedSharedPreferences`。
- F10 的"<500ms"仅实现了逻辑，无耗时埋点/验收记录。
