## 二、逐项说明

### 1. WebDAV 明文 HTTP（阻断）

- **根因**：`targetSdk = 34`，API 28 起 `cleartextTrafficPermitted` 默认 false，而 Manifest 未声明任何网络策略。
- **关键认知**：`WebDavClient.buildClient()` 里的 `ConnectionSpec.CLEARTEXT` **不解决这个问题** —— `ConnectionSpec` 只声明协议协商范围，平台网络策略才是闸门。
- **改动**：
  - 新增 `app/src/main/res/xml/network_security_config.xml`：`base-config cleartextTrafficPermitted="true"`。
    之所以不能用 `domain-config` 精确放行：WebDAV 地址由用户填写（局域网 NAS 形如 `http://192.168.1.10:5005/webdav`），而 `<domain>` 只接受字面主机名/IP，**不支持 CIDR 网段**，无法预先枚举。取舍与风险已写在配置文件注释里。
  - Manifest `<application>` 增加 `android:networkSecurityConfig="@xml/network_security_config"`（已在打包后的清单中确认生效）。
  - 设置页填入 `http://` 地址时弹提示：凭据与书籍内容将明文传输，建议 https 或仅在可信局域网使用。
- **影响面**：本应用网络出口只有 `WebDavClient` 一处（书籍同步），不存在其他被放开的调用点。

### 1b. PROPFIND href 解析错误（阻断，排查中发现）

- **根因**：原 `WebDavClient.absolute()` 把所有 href 一律当作「相对 base 的路径」拼接：
  ```kotlin
  val base = if (baseUrl.endsWith("/")) baseUrl else "$baseUrl/"
  return base + href.trimStart('/')
  ```
  RFC 4918 规定 `D:href` 是 **URI 引用**，主流服务端（sabre/dav、Nextcloud、Apache mod_dav、IIS）返回的是**路径绝对引用**（以 `/` 开头）。于是：
  ```
  base = https://host/remote.php/dav/files/u/ReadIt/
  href = /remote.php/dav/files/u/ReadIt/book.pdf
  结果 = https://host/remote.php/dav/files/u/ReadIt/remote.php/dav/files/u/ReadIt/book.pdf   ← 404
  ```
- **为什么之前没暴露**：上传路径的 href 是本地拼出来的（`/ReadIt/x.pdf`），刚好能吃下这个错误逻辑；**只有「远端新增 → 下载」这条路会踩到**，且失败被收敛进 `SyncReport.failed`，表现为「同步跑了但什么都没下载」，极难排查。
- **改动**：
  - 新增 `com.readit.sync.webdav.DavUrl`：`resolve()` 按 RFC 3986 §5.3 区分「绝对 URL / 路径绝对引用 / 相对引用」三种形态；另提供 `normalizeInput()`（补 scheme、去尾斜杠）、`isCleartext()`、`encodeSegment()` / `encodePath()`。
  - `WebDavClient` 现在把 `remoteDir` 收进构造参数，一次性算出 `collectionUrl`，避免「用户配置的目录」与「服务端返回的 href」两种语义混用；新增 `urlOf(name)` 供上传与基线记录复用。
  - API 收敛为语义明确的 `list()` / `download(href)` / `upload(name, ...)`，`WebDavSync` 不再自己拼 href（删除 `hrefFor`）。
- **回归**：新增 `DavUrlTest` **19 个用例**，其中专门有一条 `assertNotEquals(base + href.trimStart('/'), got)` 把旧的错误拼法钉死。

### 1c. 手动性能档位切换未生效（重要，排查中发现）

- **根因**：`perf_tier` 是 EAL 检测阶段的输入（`DeviceProfileDetector.detect()` 读它），但 `Eal` 在进程内缓存了检测结果，设置页改完偏好后没有触发重算 → 用户切换档位后必须重启应用才生效，直接影响 F20「六档组合正确切换」与 F17 的手动覆盖验收。
- **改动**：档位变更后调用 `Eal.reload()` 并回显新档位；刷新模式变更后调用 `RefreshModeManager.apply(mode)`；两者都即时刷新设置页底部的 `eal_summary`。

### 2. TalkBack（重要）

- **控件层已补齐**：书架列表项、阅读页目录项的 `contentDescription` 补上角色语义；3 个 SeekBar 补标签（SeekBar 自身只会读「seek bar, 40 percent」）；排版数值标签、页码、书架空态加 `accessibilityLiveRegion="polite"`。
- **修正审核报告中的一处不准确判断**：工具栏按钮与设置项**本来就已可读**（`android:text` 即朗读内容），此前记为「缺失」有误；若再叠加 `contentDescription` 反而会覆盖原文案。真正的缺口是 SeekBar、动态数值与列表项语义。
- **正文层**：TxtCanvasView 为 Canvas 自绘、无法产生无障碍节点，改为提供方位描述「正文区域，第 N 页，共 M 页」。完整评估结论、不实现 `AccessibilityNodeProvider` 的理由、以及 F30 进 P1 后的实现预案，见 `docs/R18 TalkBack 可读性评估结论.md`。R18 由「未评估」转为「已定界」。

### 3. F18 设备配置手动导入（重要）

- 设置页「性能与显示」新增「导入设备配置」项，走 SAF（`ActivityResultContracts.OpenDocument`，MIME 用 `*/*` 以兼容各家文件管理器），落到 cache 临时文件后交给 `DeviceRepository.importProfiles()`。
- `importProfiles()` 改为返回导入的设备条目数，空列表与解析失败都抛 `IOException`；导入成功后调用 `Eal.reload()`，新配置立即生效。
- 至此 F18「内置 + 手动导入」两条路径闭合。

### 4. PDF 渲染超时看门狗（重要）

- `PdfRenderView` 新增 `renderTimeoutMs`（默认 8s）与 `onRenderTimeout` / `onPageRendered` 回调；看门狗只对「自己仍是最新请求」的情况触发（`mySeq == seq`），避免用户连点翻页时旧页超时打扰上层。
- `ReaderActivity` 维护连续超时计数，成功渲染一页即清零；单次超时给 Toast 提示（用户可翻页绕开），**连续 3 次超时**判定为本机带不动 Pdfium 渲染档，整本退到 PDF 文本档并给出对应文案。
- 这样 R11「Pdfium A33 级渲染超时」从「只有兜底、没有检测」变成「有检测 + 有降级」。
